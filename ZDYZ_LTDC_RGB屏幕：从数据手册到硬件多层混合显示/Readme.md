# 🚀 STM32H750 驱动 RGB 屏幕实战：从数据手册到硬件多层混合显示

本项目旨在帮助开发者理解如何从零开始驱动一块 RGB 液晶屏，并深入掌握 STM32H7 系列强大的 **LTDC（Liquid Crystal Display Controller）** 硬件混合加速特性。

> **参考资源与教学：** [如何设置 LTDC 并验证移植成功案例](https://cloud.tencent.com/developer/article/1851969)

---

## 📑 1. 案例简介
本案例基于 **STM32H750** 处理器与 **4.3寸 RGB 屏幕 (ATK4384, 800x480)**。

### 🎯 核心目的：
* **验证硬件稳定性**：通过大批量像素填充验证外扩 SDRAM 的读写可靠性。
* **掌握时序转换**：学会将屏幕数据手册（Datasheet）中的抽象参数转换为 LTDC 寄存器配置。
* **演示硬件融合 (Blending)**：利用 H7 双层硬件加速，演示无需 CPU 参与的图像透明度叠加效果。

---

## 🧠 2. 关键时钟配置 (30MHz 像素时钟)

根据屏幕规格书，像素时钟（PCLK）的典型值为 **30MHz**。在 STM32CubeMX 中通过 `PLL3R` 生成：

* **配置参数**：
    * **HSE**: $25\text{ MHz}$
    * **PLL3M**: $5$ | **PLL3N**: $120$ | **PLL3P/Q**: $2$ | **PLL3R**: $20$
* **计算公式**：
    $$\text{PCLK} = \frac{HSE}{PLL3M} \times \frac{PLL3N}{PLL3R} = \frac{25}{5} \times \frac{120}{20} = 30\text{ MHz}$$

> [!CAUTION]
> **频率陷阱**：PCLK 频率设置过高会导致屏幕闪烁或花屏；设置过低会导致刷新率不足（低于 60Hz），产生明显的肉眼可见闪烁感。

---

## 🛠️ 3. 硬件引脚注意事项

由于 RGB 信号属于高频并行传输（30MHz）：
1.  **引脚速度**：在 CubeMX 中，**必须**将所有 LTDC 相关引脚的 `Maximum Output Speed` 设置为 **"Very High"**。
2.  **信号完整性**：未设置高速模式会导致波形跳变沿变缓，产生严重的显示错位或色彩漂移。

## 💻 4. 软件实现细节

### 4.1 背光开启 (Backlight)
> [!IMPORTANT]
> **点亮顺序**：在初始化显示控制器之前，必须先点亮背光，否则无法看到任何输出。

```c
/* 在 main.c 中调用 */
// 1. 手动拉高背光引脚（必须放在 LTDC 初始化之前）
HAL_GPIO_WritePin(LCD_BL_GPIO_Port, LCD_BL_Pin, GPIO_PIN_SET); 

// 2. 初始化显示控制器
MX_LTDC_Init();
```

### 4.2 显存分配与多层混合实验
本案例开启了两个层（Layer 0 和 Layer 1），通过向 SDRAM 写入不同颜色验证硬件混合：

* **层 0 (Layer 0)**：全屏 800x480，填充纯蓝色，Alpha=255 (100% 不透明)。
* **层 1 (Layer 1)**：中心 400x240 窗口，填充纯红色，Alpha=127 (50% 透明)。

**关键实现代码：**

```c
/* 在 MX_LTDC_Init 的 USER CODE 0 中预填显存数据 */
uint16_t *ltdc_fb0 = (uint16_t *)0xC0000000;                 // 层0起始地址
uint16_t *ltdc_fb1 = (uint16_t *)(0xC0000000 + 800 * 480 * 2); // 层1紧跟层0之后

// 填充层0为蓝色
for (uint32_t i = 0; i < (800 * 480); i++) ltdc_fb0[i] = 0x001F; 

// 填充层1为红色
for (uint32_t i = 0; i < (400 * 240); i++) ltdc_fb1[i] = 0xF800;

/* 在 LTDC_Init 2 结尾放置死循环用于观察效果 */
/* 读者应观察到：背景为蓝色，中心矩形因为红蓝混合呈现出“紫色” */
while(1); 
```

## ⚠️ 5. 开发者必读 (避坑指南)

1.  **地址重叠 (Memory Conflict)**：层 0 和层 1 的 `FBStartAdress` 绝不能重叠，必须根据 `分辨率 * 位深` 计算出足够的偏移量，否则画面会撕裂。
2.  **MPU 与 Cache**：SDRAM 区域必须配置 MPU 保护。建议设置为 **Normal 模式** 并开启 **Write-back Cache**，否则画屏速度会非常缓慢。
3.  **累计参数 (Accumulated)**：CubeMX 中的 HSYNC/VBP 等填入的是**累计值（Accumulated）**，即 `Porch值 + 同步脉冲宽度`，而非数据手册上的单个独立值。

## 💡 进阶应用建议

在实际的 **电力仪表产品** 中，可以充分利用 LTDC 的“层”特性：
* **层 0 (底层)**：专门用于绘制波形、实时曲线等高频刷新内容。
* **层 1 (顶层)**：用于放置 UI 菜单、按钮和静态文字。
* **效果**：当用户滑动菜单时，底层的波形无需重绘，由硬件直接叠加显示。这能极大降低 H7 的 CPU 占用率，确保波形显示的流畅度。

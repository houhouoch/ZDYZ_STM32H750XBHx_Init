# 🚀 STM32H750 高性能数字电源控制器 (Pro 版)

本项目是一款基于 **STM32H750VBT6** 的工业级数字电源控制系统。它深度整合了 **LVGL v8.3** 图形界面、**FDCAN** 通信协议栈以及多机并联同步逻辑，旨在解决高性能 MCU 在处理复杂 UI 与多任务实时同步时的典型痛点。

---

## 🧠 一、 系统核心架构 (System Architecture)

系统采用 **“三层解耦”** 设计，确保高频通讯不干扰 UI 响应，UI 操作不影响控制精度。



### 1. 硬件抽象与资源层 (HAL & Resources)
* **FDCAN 引擎**：配置为 Classic 模式（500k/1M）。利用 H7 专有的 **32 深度硬件 FIFO0** 缓解中断压力，在高频下位机回传场景下实现“零丢包”。
* **双重过滤机制**：结合掩码过滤（Mask）与列表过滤（List），从硬件层屏蔽非法报文，显著降低 CPU 负荷。
* **内存优化**：针对 AXI SRAM 进行数据布局，关键状态结构体 `PowerInfo` 使用 `volatile` 修饰，确保多任务数据强一致性。

### 2. 中间接口层 (Interface Layer - The "Buffer")
* **单一真相来源 (SSOT)**：所有数据操作均通过 `IF_Power_Set_...` 系列接口，配合**递归互斥锁 (Recursive Mutex)** 防止竞态条件。
* **事件触发机制**：引入 `canUpdata_event` 标志位，仅在参数变更时触发总线推送，避免无效通信占满带宽。

### 3. 应用逻辑层 (Application Layer)
* **点火时序控制**：执行“数据预设 -> 硬件同步 -> 物理使能”闭环。通过 100ms 缓冲逻辑，解决硬件启动瞬间因参数未就绪导致的误保护。
* **响应式 UI**：利用 LVGL Timer 实现 200ms 周期刷新，具备**焦点状态感知**功能，防止自动同步覆盖用户的正在编辑值。

## 📡 二、 FDCAN 通信协议深度解析

### 1. 29 位扩展 ID 定义 (位域解析)

本项目通过 C 语言联合体（Union）实现了 ID 的“零成本”拆解：

| 位域 (Bits) | 含义 | 技术细节 |
| :--- | :--- | :--- |
| **Bit 28** | 数据方向 (DIR) | 0: 主机下发命令; 1: 从机应答/回传 |
| **Bit 24-27** | 指令类型 | 1: 动作控制 (ORDER); 5: 参数设置 (SET) |
| **Bit 16-18** | 设备类型 | 1: BUCK; 2: LLC; 3: PFC |
| **Bit 0-7** | 站号 (Addr) | 支持 0-255 个节点的独立寻址 |

### 2. 参数打包与字节序 (Big-Endian)

为确保跨平台兼容，浮点数统一采用大端序存储。禁止直接指针强转，推荐使用联合体进行字节调换：

```c
// 电压参数转换示例：12.0V -> [0x41, 0x40, 0x00, 0x00]
union { float f; uint8_t b[4]; } conv;
conv.f = voltage;
tx_msg.data[4] = conv.b[3]; // MSB
tx_msg.data[5] = conv.b[2];
tx_msg.data[6] = conv.b[1];
tx_msg.data[7] = conv.b[0]; // LSB
```

### 3. 波特率计算公式
$$Bitrate = \frac{F_{fdcan\_clk}}{Prescaler \times (1 + TS1 + TS2)}$$

## 📅 三、 任务调度与资源管理

### 1. 优先级映射表 (FreeRTOS)

| 任务名称 | 周期 | 优先级 | 职责 |
| :--- | :--- | :--- | :--- |
| **CAN_Msg_Process** | 事件触发 | **AboveNormal** | 解析接收帧并执行 Action 指令 |
| **CAN_Tx_Scheduler** | 50ms | **Normal+1** | 维护同步计数器，下发 Modbus 及使能脉冲 |
| **GUI_Task** | 5ms | **Normal** | 维护 LVGL 节拍及定时器运行 |

### 2. 关键文件组织
* **can_manager.c**: 核心协议层，包含大端序封装及发送调度状态机。
* **CAN_IRQ_Task.c**: 业务隔离带，负责 `IF_Power_` 系列接口实现。
* **HomePage.c**: UI 事件回调与刷新定时器逻辑。

## 🛠️ 四、 避坑指南 (Lessons Learned)

* **“点不着火”的 Output**：
    * **现象**：指令已发，UI 已变，但硬件无输出。
    * **教训**：必须遵循“数据同步 100ms 后下发 10ms 物理使能脉冲”的逻辑，确保 Modbus 设置已在下位机生效。
* **串口阻塞导致的“假死”**：
    * **现象**：`printf` 密集打印浮点数时 CAN 丢包。
    * **对策**：引入 `print_counter` 实现 1s 降频打印，并将波特率提升至 460800 以上。
* **Keil 调试“变量消失术”**：
    * **现象**：变量在 Watch 窗口不更新，无法打断点。
    * **对策**：-O2 优化等级下变量被分配至寄存器。调试阶段建议设为 **-O0**，或将关键变量声明为 `volatile`。
* **UI 数据跳变冲突**：
    * **对策**：在刷新定时器中加入 `if(lv_obj_has_state(obj, LV_STATE_FOCUSED))` 检查。若用户正在调节编码器，则跳过该部件的自动同步。

## 🚀 部署建议

1.  **向量表偏移**：若使用 Bootloader，请务必在 `main()` 开始处设置 `SCB->VTOR`。
2.  **MPU 配置**：建议将 FDCAN 的 Message RAM 区域配置为 **Non-cacheable**，防止数据一致性错误。

# 🚀 STM32H750 DMA2D 绘图加速器移植指南

本项目记录了如何利用 **STM32H750** 的 **Chrom-ART (DMA2D)** 硬件加速器，配合 **LTDC** 控制器与外部 **SDRAM** 实现高效的屏幕驱动。本指南为后续接入 **LVGL** 图形库提供了坚实的硬件加速基础。

---

## 🛠️ 1. 核心配置参数详解

在移植 DMA2D 时，以下三个核心公式决定了图像显示的正确性。为了避免 GitHub 渲染错误，变量名已去以下划线。

### 📍 1.1 显存地址定位 (OMAR 寄存器)
由于采用 **RGB565** 格式（每个像素占用 2 字节），且本方案显存设在 SDRAM 处，计算逻辑如下：

$$Address = 0xC0000000 + 2 \times (800 \times y + x)$$

* **$0xC0000000$**：外部 SDRAM 的物理基地址（Bank 1）。
* **$800$**：屏幕的物理宽度（Pixel）。
* **$2$**：RGB565 格式下单像素占用的字节数。

### ↔️ 1.2 输出偏移量 (OOR 寄存器)
输出偏移量（Offline）决定了 DMA2D 完成一行扫描后，需要跳过多少像素才能进入下一行的起始点：

$$Offline = 800 - FillWidth$$

* **$FillWidth$**：当前需要填充或搬运的矩形区域宽度。
* **作用**：当填充区域小于屏幕总宽（800）时，通过此偏移确保矩形在屏幕上位置准确。若全屏填充，则 $Offline = 0$。

### 📐 1.3 区域尺寸定义 (NLR 寄存器)
该寄存器通过高低 16 位分别定义矩形的高度和宽度：

$$NLR = (FillHeight) \ | \ (FillWidth \ll 16)$$

* **$FillHeight$**：待绘矩形的高度。
* **注意**：必须严格遵循此位域分布（高 16 位宽，低 16 位高），否则会产生画面拉伸或错位。

## 🖌️ 2. 核心函数接口说明

### 🟦 函数 A：`ltdc_fill` (快速单色填充)
* **工作模式**：**R2M** (Register-to-Memory)。
* **原理**：将颜色数据直接从 DMA2D 内部寄存器“喷射”到显存。
* **优势**：零内存源开销，且免疫 Cache 一致性风险。
* **场景**：清屏、绘制 UI 背景。

### 🟩 函数 B：`ltdc_color_fill` (图像/缓冲区搬运)
* **工作模式**：**M2M** (Memory-to-Memory)。
* **原理**：将数据从内部 SRAM 缓冲区（如 LVGL 渲染池）高速搬运至 SDRAM 显存。
* **H7 关键操作**：
    > [!IMPORTANT]
    > **D-Cache 管理**：在启动搬运前，必须执行 `SCB_CleanDCache_by_Addr` 清理源缓冲区（SRAM）。否则 DMA2D 可能会搬运过期的缓存数据，导致屏幕出现色彩断层。

---

## ⚠️ 3. H7 移植注意事项 (避坑指南)

1.  **存储区域 MPU 保护**：若定义的大型数组（如测试缓冲区）位于局部变量（栈区），极易触发 MPU 硬件异常。建议将缓冲区定义为 `static` 全局变量，并分配在 **AXI SRAM** 区域。
2.  **防御性标志清理**：为确保系统实时性，应在启动 DMA2D 前清除旧的中断标志位，并按顺序开启：
    ```c
    DMA2D->IFCR |= DMA2D_IFCR_CTCIF; // 清除传输完成标志
    DMA2D->CR |= DMA2D_CR_START;     // 启动加速器
    ```

## 📈 4. 后续扩展：对接 LVGL

本项目的核心价值在于验证了 **M2M 搬运逻辑**。在移植 LVGL 时，只需将 `ltdc_color_fill` 封装进 `disp_flush_cb` 接口，即可实现完全脱离 CPU 负载的 UI 全速刷新。

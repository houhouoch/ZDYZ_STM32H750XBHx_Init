# 🚀 STM32H750 DMA2D 绘图加速器移植指南

本项目记录了如何利用 **STM32H750** 的 **Chrom-ART (DMA2D)** 硬件加速器，配合 **LTDC** 控制器与外部 **SDRAM** 实现高效的屏幕驱动。本指南为后续接入 **LVGL** 图形库提供了坚实的硬件加速基础。

---

## 🛠️ 1. 核心配置参数详解

在移植 DMA2D 时，以下四个核心寄存器的参数配置决定了图像显示的正确性：

### 📐 1.1 区域大小 (NLR 寄存器)
* **参数**：`Number of Line` (高 16 位) & `Pixel per Line` (低 16 位)。
* **配置逻辑**：
  ```c
  DMA2D->NLR = (height) | (width << 16);
  ```
* **注意**：此处的高宽是指**待填充矩形**的尺寸，而非物理屏幕的总尺寸。

### 📍 1.2 地址计算 (OMAR 寄存器)
* **计算公式**：
  $$\text{Address} = \text{BaseAddr} + 2 \times (\text{Screen\_Width} \times y + x)$$
* **细节**：由于实验统一采用 **RGB565** 格式，每个像素占用 **2 字节**，因此偏移量必须乘以 2。

### ↔️ 1.3 输出偏移 (OOR 寄存器)
* **计算公式**：
  $$\text{Offline} = \text{Screen\_Width} - \text{Fill\_Width}$$
* **作用**：告诉硬件在画完一行后，需要跳过多少个像素才能到达下一行的起始位置。若为全屏填充，此值为 0。

### 🎨 1.4 颜色格式 (CCR)
必须确保 **前景层 (FGPFCCR)** 与 **输出格式 (OPFCCR)** 与 LTDC 的层配置严格一致（本实验统一为 RGB565）。

## 🖌️ 2. 核心函数接口说明

### 🟦 函数 A：`ltdc_fill` (快速单色填充)
* **工作模式**：**R2M** (Register-to-Memory)。
* **原理**：将颜色数据直接从 DMA2D 内部寄存器“喷射”到显存地址。
* **优势**：
    * **零内存开销**：无需定义额外的缓冲区。
    * **免疫 Cache 风险**：数据不经过内存读取，不存在 Cache 不一致导致的“虚假显示”。
* **适用场景**：清屏、绘制 UI 背景、简单矩形框。

### 🟩 函数 B：`ltdc_color_fill` (图像/缓冲区搬运)
* **工作模式**：**M2M** (Memory-to-Memory)。
* **原理**：将数据从 SRAM 缓冲区（如 LVGL 渲染池）高速搬运至 SDRAM 显存。
* **H7 必做操作**：
    > [!IMPORTANT]
    > **D-Cache 管理**：在启动搬运前，必须调用 `SCB_CleanDCache_by_Addr`。否则 DMA2D 可能会搬运 RAM 里的旧数据，导致屏幕出现撕裂或显示不全。
* **适用场景**：显示图标、动态波形刷新、**LVGL `disp_flush` 接口对接**。

---

## ⚠️ 3. H7 移植关键注意事项 (避坑指南)

### 1️⃣ 存储架构与 MPU 保护
STM32H7 拥有复杂的 AXI/ITCM/DTCM 总线架构。
* **坑点**：若将大型测试数组（如 `test_buffer`）定义在局部变量（栈区），极易触发 **MPU 保护中断** 或导致堆栈溢出。
* **对策**：大型绘图缓冲区应定义为 `static` 或全局变量，并建议分配在 **AXI SRAM** 或 **SRAM1** 区域。

### 2️⃣ 中断与标志位清除顺序
为了保证工业级的实时性，本项目采用 **“防御性”** 清除逻辑，确保中断不被漏触发：
1. **预清除**：`DMA2D->IFCR |= DMA2D_IFCR_CTCIF;` (防止旧标志干扰)。
2. **使能**：`DMA2D->CR |= DMA2D_CR_TCIE;` (开启传输完成中断)。
3. **启动**：`DMA2D->CR |= DMA2D_CR_START;`。

---

## 📈 4. 后续扩展：对接 LVGL

本项目的核心价值在于验证了 **M2M 搬运逻辑**。在后续移植 LVGL 时，只需将 `ltdc_color_fill` 封装进 `disp_flush_cb` 回调函数中，即可实现完全不占用 CPU 负载的 UI 全速刷新。

### 💡 作者小结
* **R2M 负责“打底”** (高效清屏)。
* **M2M 负责“贴图”** (UI 渲染)。

两者结合，在 **480MHz** 的 H750 强力驱动下，可以实现几乎**零延迟**的电力测量仪表界面响应，为复杂电力波形的实时绘制提供了性能保障。
